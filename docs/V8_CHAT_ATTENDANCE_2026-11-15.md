# v8 대화 유지 · 입장 안내

2026-11-15 사용자 후속 요청은 앞선 8초 표시/1초 페이드 규칙을 대체한다. 대화는 시간이 지나도 사라지지 않는다. PC 최근 5개, 모바일 최근 3개를 유지하며 새 항목이 오면 오래된 항목부터 화면에서 밀려난다. 기록 창은 대화와 시스템 안내를 합쳐 이번 접속 최근 60개를 보관한다. 새로고침 뒤 서버에서 복원하는 영구 기록은 아니다.

입력줄은 Enter/대화 버튼으로 열고 성공한 전송 뒤에만 닫는다. 실패 초안, 한글 조합, 중복 전송 방지, 늦은 응답의 새 초안 보호, 모바일 키보드/캔버스 크기 보호는 유지한다. 짧은 화면에서 최신 메시지를 잘랐던 100px 피드 높이 제한을 제거했다. 행마다 최대 두 줄, PC 5개/모바일 3개 상한은 그대로다.

## 입장 안내의 실제 의미

- 내 프로필 설정이 끝나면 이 페이지에서 한 번 `나의 입장 · ○○님, 도량에 오신 것을 환영합니다.`를 표시한다. 이것은 서버가 내 출석을 인증했다는 뜻이 아니다.
- 온라인 연결의 최초 명단은 `접속 안내 · ○○님이 함께하고 있습니다.`로 표시한다. 처음 보인 명단을 신규 입장으로 단정하지 않는다.
- 최초 명단 이후 join을 받고, 이름과 유효한 위치/장면을 실제로 관찰한 참가자는 `접속 안내 · ○○님이 도량에 오셨습니다.`로 표시한다.
- 확인된 join 구분 없이 위치를 먼저 관찰한 경우에는 중립적인 `함께하고 있습니다`를 사용한다. 이름이 없는 join만으로 임의 이름을 만들어 표시하지 않는다.
- 로컬 BroadcastChannel의 다른 탭은 `이 브라우저 · ○○님이 이 브라우저에서 함께하고 있습니다.`로 구분한다. 다른 기기의 온라인 입장으로 표현하지 않는다.
- 중복 방지는 페이지 세션 내 방 이름+참가자 ID 기준이다. 같은 ID의 위치 갱신, 장면 전환, 연결 메타/세션 변경, 일시 퇴장/재연결은 다시 알리지 않는다. 실제 같은 ID가 다시 방문하더라도 이 페이지에서는 한 번만 알린다. 새 ID와 새 방, 새로 연 페이지는 별개다.
- Supabase는 기존 공간별 위치 전달 구조를 유지하므로 이름 있는 위치를 아직 받지 못한 다른 공간 참가자의 안내는 지연되거나 나타나지 않을 수 있다. 전체 접속자를 실명으로 확인한 출석부가 아니다.

Relay 클라이언트는 welcome snapshot에서 만든 join에 `initial:true`, 이후 새로 관찰한 join에는 `initial:false`를 **내부 콜백에만** 붙인다. Supabase 클라이언트는 SDK의 최초 presence sync 이전 join과 이후 join을 구분하고 재연결 시 이 구분을 재설정한다. 서버 프로토콜·Worker·DB·network.js는 바꾸지 않았다.

시스템 안내는 이 화면의 대화 배열에만 추가하며 네트워크 chat으로 전송하거나 DB에 쓰지 않는다. 말풍선도 만들지 않는다. 이름과 안내는 textContent로 표시하여 HTML로 해석하지 않는다. 모든 이름은 현재 사용자가 입력한 표시 이름이다. 실명 인증/관리자 명단 승인 구현은 사용자 요청에 따라 별도 TODO로 남겼다.
