# v8 게임 중 일시 대화

## 적용

- 평소 PC/모바일의 상시 패널을 없애고 대화 글만 왼쪽 위에 표시한다. PC 5개/모바일 3개, 로컬 수신 시점부터 8초 유지 후 1초 동안 사라진다. 화면에 안 보여도 이번 접속의 최근 60개에는 남는다.
- Enter 또는 대화 버튼으로 입력줄을 연다. 전송 성공 시 닫고 실패 시 초안을 유지한다. 한글 조합, 빈 Enter, Esc, 늦은 전송 응답의 기존 보호를 유지한다.
- 기록 버튼으로 최근 대화를 읽는다. 읽는 중 새 글이 와도 스크롤 위치를 보존하며 '새 대화 · 최신으로'로 최신 위치에 갈 수 있다. 기록 닫기는 게임으로 돌아가고 '대화 쓰기'는 입력을 다시 연다.
- 모바일 키보드 위 입력줄은 보내기/기록/닫기를 함께 표시한다. 입력 중 조작 버튼을 숨기며 키보드로 레이아웃 높이가 줄어도 캔버스 크기를 보존한다. 실패 알림도 입력줄을 덮지 않는다.
- 기존 서버·채팅 전송·저장 계약을 유지한다. 영구 대화 저장이나 팀별 채팅은 추가하지 않았다.

## 검증

- Node 회귀는 8초 유지/9초 만료, PC5/모바일3, 한글 조합과 전송 실패/늦은 응답 초안을 포함한다.
- `qa-v8-enter-chat.cjs`: PC1280×900, 모바일390×844, 키보드 모형390×460, 가로844×390. 로컬 BroadcastChannel 실제 수신, 실제 타이머 만료, 60개 상한/앞 글 제거 중 읽던 행 유지, 새 글 이동, 지도 키 회귀, 키보드 높이 변화의 캔버스 보존, 다른 모바일 메뉴의 키보드 초점을 확인한다.
- `qa-v8-chat-dom.cjs`: 좁힘→넓힘→좁힘에서 시간순/개수 유지, 기록에서 Ctrl+C 기본 동작 허용, 만료한 글 재등장 방지, UI 정리를 확인한다. 좁은 창에서 넓혔을 때 과거 글이 뒤에 붙는 문제는 독립 검토에서 발견해 실패→성공으로 검증했다.
- 브라우저 테스트는 WebSocket/DB 쓰기를 차단하고 같은 브라우저의 BroadcastChannel을 사용한다. 운영 대화방에 시험 글을 보내지 않는다. 실제 iPhone Safari의 소프트 키보드/IME와 운영 릴레이 송수신은 검증 못 했음.
- 전체 Node 테스트 367개, production build, diff check 통과. PC/모바일 실제 브라우저 흐름과 독립 DOM 검증 모두 통과했고 페이지 오류는 0건이다. 기존 큰 번들 경고는 남아 있다.
