# v8 위치 전송 최적화

기준 main: 0acc7befdf624c284fec7a574134b81d565ed823. 사용자가 정지 전송 중단·속도 기반 예측·인원별 간격·장소별 전송을 승인했다.

## 변경
- 100ms는 기기 내부의 위치 샘플 간격이다. 네트워크 전송 간격이 아니다. 정지 중 주기 재방송은 없으며, 일정한 속도로 움직일 때도 예측 오차가 작으면 재방송하지 않는다.
- 이동 시작/정지/순간 이동/외형 변경은 전달하고, 오차 보정·회전 전송 간격은 방 인원에 따라220/450/900/1500ms로 조절한다. moving checkpoint는 인원·id에 따라 분산하며 최장36초 안에 갱신한다. 수신 예측은40초로 제한한다.
- `v8:<room>`은 방 전체 Presence/대화를 유지한다. 위치와 인사는 `v8:<room>:scene:<scene>`에만 보낸다. 같은 Supabase SDK 소켓을 공유하며 추가 SDK/DB/서버/환경변수 변경이 없다.
- 늦은 입장자 스냅샷은 자기 inbox로만 받는다. SDK의 명시적 httpSend를 쓰며 DB 저장이 아니다. 요청 세대 토큰을 검사하고, HTTP 실패는 최대3번까지 직접 재시도한다. 진행 중/성공한 중복 요청은 재방송하지 않는다.
- 글로벌 참가자 ref 집합과 connect 세션 식별자를 유지한다. 퇴장·장소 이력은 아바타와 별도로 보관해 지연 응답의 유령 인형을 막는다. 방 수는 위치 패킷 수와 별도로 계산한다.
- SDK가 같은 topic 채널을 재사용하므로 퇴장 완료를 기다린 뒤 새 채널을 만든다. 빠른 장소 왕복·이전 콜백·인박스 재구독·연결 복원·HTTP 실패 재시도를 검증했다.
- 지도·시설 좌표·제작·저장·성장·채팅 초안·BFCache 정책은 유지한다. 기존 열린 탭은 새로고침해야 새 전송 방식을 쓴다.

## 검증 및 판단 기록
- 기존 서버 부하 시험은10명 지속 이동도 초당 메시지 제한으로 끊겼다. 당시 raw 결과는 실행 작업공간의 v8-capacity에 보관했다.
- 전체 테스트/빌드와 실제 서버 부하 결과는 아래 최종 검증 절에 기록한다.
- 실제 독립 PC/모바일 브라우저에서 접속·위치·대화·인사·장소 격리·외형·방 분리·재입장·정지 상대 유지·소켓 재연결과 초안 보존·BFCache·닫기 퇴장12항목을 확인했다. 날씨 API의 환경 CORS 오류는 통신과 분리돼 있었고 pageerror는0이었다.
- 독립 최종 코드 검토의 Important3건(동일 topic 퇴장 중 재사용, 지연 스냅샷의 퇴장 인형 부활, 진행 중 HTTP 실패 뒤 재시도 유실)을 모두 회귀 테스트 RED→GREEN으로 수정했다. 실제 SDK 채널 재사용도 포함했다. 연관된 접속 세션/빠른 왕복의 최종 장소 공지/재연결 참가자 집합 유지도 검증했다.
- 공개 방의 인증/영구 기록/공동 제작으로 표현하지 않는다. 스냅샷용 HTTP는 Realtime broadcast API이며 운영 DB 쓰기가 없다.
- 초기40명 직선 이동60초 시험은 전원 유지, 위치140회(기존 예상6864회 대비 약98% 감소), 최종 위치·늦은 입장·퇴장 통과였다. 이는 최종 예외 수정 전 측정이며 최종 빌드의 반복 방향/분산 장소 결과와 구분한다.

## 재현
선택 개발 도구 Playwright와 Chromium이 필요하다. 운영 의존성은 추가하지 않았다. npm run build 후 npm run preview -- --host 0.0.0.0 --port 5198을 실행하고 저장소 루트에서 scripts/qa-v8-motion.cjs를 실행한다. BASE/COUNTS/DURATION/TURN/SPREAD/RESULT/QA_OUTPUT 환경변수로 조건과 출력 위치를 정한다. 예: COUNTS=20 DURATION=60 TURN=10 또는 COUNTS=40 SPREAD=4 TURN=6 DURATION=60.
시험은 별도 qa 방에서 실제 배포 통신 모듈을 사용한다. 전원 참가를250ms 이상(40명은1.6초 간격)으로 나누어 부트스트랩 폭주를 피했다. 한 기기 안의 독립 WebSocket 연결을 늘린 합성 시험이며 실제40대 기기·40명 동시 클릭·iPhone/Safari GPU/FPS·장시간 부하를 검증한 것은 아니다. 전체 서버 사용량 한도는 여전히 남으며, 한 장소에서 다수가 빠르게 계속 방향을 바꾸거나 동시에 접속하는 최악 조건의40명 보장은 하지 않는다.
