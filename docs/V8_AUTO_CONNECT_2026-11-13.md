# v8 자동 접속

사용자 요청(2026-11-13): "자동 접속되게 해줘".
지금까지는 `함께 접속` 창을 열고 방 이름을 적어 단추를 눌러야 연결됐습니다.

## 무엇이 달라지나

- 이름을 정하고 도량에 들어가면 **저절로 `hanmaum` 방에 붙습니다.** 아무것도 안 눌러도 됩니다.
- 다른 법우가 같은 시간에 들어오면 **서로 보입니다.**
- `접속 나가기` 를 누르면 꺼지고, **새로고침해도 꺼진 채로** 있습니다. 다시 `함께 접속` 을 누르면 켜집니다.
- 켜고 끈 선택과 방 이름은 `hanmaum-journey-online` 에 그 브라우저에만 저장합니다.

## 어떻게

`public/v8.html` 의 `HanmaumLocalChat` 네 군데만 고쳤습니다. 통신·화면·게임 규칙은 그대로입니다.

- `autoConnect()` — 붙일지 말지만 정합니다. 아래를 모두 만족할 때만 붙습니다.
  - 직접 끄지 않았고(`autoOff`), `http(s)` 로 열렸고, 아직 안 붙었고, **이름이 있고**,
    마지막 시도에서 **15초** 지났을 것
- **새 타이머를 만들지 않습니다.** 이미 0.35초마다 도는 `announce()` 안에서 부릅니다.
  시험 환경(`vm`)에 `setTimeout` 이 없어서이기도 하고, 타이머가 하나 더 늘지 않아서이기도 합니다.
- `location`·`localStorage`·`ctx.store` 가 없는 환경에서도 터지지 않게 전부 감쌌습니다.
  코덱스의 `tests/v8-integration.test.mjs` 가 그런 환경에서 이 클래스를 직접 돌립니다.
- 창으로 돌아오거나 인터넷이 돌아오면 `autoAt` 만 0으로 만들어 **다음 announce 때 바로** 다시 시도합니다.

## 확인한 것

- `node --test tests/*.test.mjs` **204 pass / 0 fail** (코덱스의 기존 v8 시험 포함)
- `npx vite build` 성공
- 미리보기(`vite preview`)에서 브라우저 두 개를 띄워 **단추를 한 번도 안 누르고**:
  - 5·10·15·20초 모두 양쪽 `state: online · room: hanmaum · peers: 1` — 서로 보임
  - Supabase Realtime WebSocket 연결 확인
- `접속 나가기` → 22초 지나도 다시 안 붙음(`autoOff: true`), 저장값 `{"room":"hanmaum","on":false}`
- **새로고침 뒤에도 꺼진 채로 유지** (처음엔 안 됐고, 저장값을 생성 시 읽도록 고쳐 해결)
- 콘솔 오류 양쪽 0

## 아직 확인 못 한 것

- 실기기 두 대(휴대폰·PC)로 같은 방에 드는 것은 못 해 봤습니다.
- **무료 한도.** 이제 들어오는 사람마다 WebSocket 을 하나씩 엽니다. 예전에는 누른 사람만 열었습니다.
  행사처럼 사람이 몰리면 한도에 먼저 닿습니다. `scripts/realtime-free-budget.mjs` 의 계산은
  80명·2시간 한 번 기준이고, 이번 변경으로 실제 접속 수가 늘어납니다. 측정은 아직입니다.
- 방이 `hanmaum` 하나뿐이라 모두 같은 방에 모입니다. 나눌 필요가 생기면 방 이름을 쓰면 됩니다.
