# v8 다중접속만 연결

사용자 요청: v8 기준 다중접속까지만 적용하고 다른 변경은 나중에 검토한다. 기존 승인 시안은 구현하지 않는다. 사용자 기존 지시에 따라 추가 승인 질문 없이 진행한다.

기존 `/api/hanmaum/*` 서버는 없어 404다. v8의 기존 채팅/접속 UI, 아바타, 장면, 위치 보간을 유지하고 통신 계층만 기존 Supabase Realtime public channel로 연결한다. 별도 Vercel SSE 메모리 서버는 인스턴스 간 상태 보장이 없고, 기존 Worker는 v8 좌표/외형/방 프로토콜과 다르므로 사용하지 않는다.

범위: 채팅에서 같은 방 이름으로 접속, 다른 브라우저/기기의 이름·모습·장면·위치·인사·대화 전달, 퇴장 정리, 네트워크 복귀. 진행/등/경험치·DB 스키마·화면·제작순서·수동 탑돌이는 변경하지 않는다. 방 이름은 기존처럼 영문/숫자/_/- 1~32자다. 공개 방이며 비밀번호나 계정 인증을 추가하지 않는다.

온라인 참가자는 Realtime Presence로 퇴장을 판단한다. 좌표는 Broadcast만 사용하고 동일 위치 송신은 줄이되 기존 v8 상대 갱신과 호환한다. 대화 전송 실패/연결 중에는 초안을 보존한다. 기존 local BroadcastChannel은 온라인일 때 중복 사용하지 않는다.

Vite 별도 JS entry로 transport를 번들하고 public/v8.html은 기존 한 파일을 유지한다. VITE_SUPABASE_URL/PUBLISHABLE_KEY 기존 설정만 사용한다. 환경변수 값/키는 소스에 넣지 않는다. 새 라이브러리/유료 인프라/DB 쓰기는 없다.

시험: mock transport로 방 분리, 유효성, 재접속, 퇴장, 송신 실패; 독립 브라우저 컨텍스트 두 개로 실제 Realtime의 위치/채팅/퇴장 확인. 전용 임의 시험방만 쓰며 DB REST 쓰기를 차단한다. 80명 등 동시접속 상한이나 실제 iPhone 성능은 시험 없이 보장하지 않는다.
