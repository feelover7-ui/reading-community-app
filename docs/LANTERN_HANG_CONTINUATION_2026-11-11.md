# 걸이대 메시지와 점등·참배 연결 수정

기준 main cba0532. PR40 병합 후 사용자가 걸이대의 메시지 입력과 등 걸기 이후 연결을 지적했다.

## 원인과 수정

기존 메시지는 제작 마지막 미리보기에서만 적을 수 있고 걸이대는 곧바로 publish했다. 걸고 나면 제작 stage가0으로 돌아오는데 하단 이동 버튼은 stage만 보고 골조 작업대를 가리켰다. 목표 표시는 별도 로직을 써 실제 다음 활동과 달랐고 하단 안내는 작업장 밖에서 숨겨졌다.

- 걸이대에서 기존 소원을 불러와 메시지를 확인/수정하고 확인 버튼으로 건다. 선택 입력/24자 제한과 정규화, 기존 저장 API를 유지한다. 초안은 기존 제작 저장에 보존한다.
- 저장 대기 중 버튼과 메시지 입력을 잠그며 중복 저장을 막는다. 실패하면 완성 상태와 메시지를 보존하고 자동 재전송하지 않는다. 저장 도중 사용자가 다른 창을 열면 늦은 응답이 그 창을 닫거나 바꾸지 않는다.
- 걸기 성공 후 메시지와 실제 로컬/공유 저장 상태를 보여주고 장엄등 점등 또는 참배로 연결한다. 이미 밤이면 탑돌이를 기본 다음 선택으로 제공한다. 자동 행동을 강제로 시작하지 않는다.
- 점등 후에는 자동 탑돌이/동상 참배/법당 참배/자유 탐방을 선택한다. 기존 충돌 경로를 걸어 도착한 뒤 활동을 시작한다.
- visitProgress.js가 제작→걸이대→장엄등→구정탑→동상→법당의 다음 목표와 문구를 공유한다. 하단 버튼과 목표 표시가 같은 상태를 따르고 작업장 밖에서도 다음 활동 안내를 유지한다. 상단의 새 등 만들기/자유 목적지 선택은 유지한다.

## 검증과 한계

테스트135개, 빌드, git diff --check 통과. 기존 Three.js 번들 크기 경고 유지. 메시지 수정/중복 클릭/실패 보존/완료 후 다른 창 보호와 전체 다음 목표 회귀 테스트 포함.

독립 리뷰에서 대기 중 메시지 변경 유실과 늦은 완료 창 덮어쓰기를 발견해 수정했다. 해당 회귀 테스트에서 수정 전 실패/수정 후 통과 확인.

PC800×700/모바일 모형390×844에서 걸이대 메시지 수정과 새로고침용 초안 저장, 한 개의 로컬 등/메시지 저장, 실제 경로로 장엄등까지 이동해 점등, 작업장 밖 다음 안내로 탑돌이 시작/중단을 확인했다. 두 환경 pageerror0. 운영 Supabase 설정 없는 로컬 검증이며 실제 운영 DB 쓰기는 하지 않았다. 별도 API mock의 지연 응답으로 입력 잠금과 다른 방명록 창 보존도 확인했다. 실제 iPhone GPU/운영 DB/다중 사용자 부하는 미검증이다.
