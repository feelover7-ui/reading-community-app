# v8 relay 연결 (2026-11-13)

사용자 요청: Supabase 의 11명 천장을 넘기 위해 v8 을 Cloudflare relay 에 붙인다.

## 왜

Supabase broadcast 는 **보낸 1건 + 받은 사람 수**로 센다. 한 장면 n 명이면 한 번 움직일 때
n 건이라 n² 로 늘고, 무료 초당 100건에서 **11명이 천장**이다 (docs/V8_AUTO_CONNECT_2026-11-13.md).
relay(Cloudflare Durable Object) 는 받는 사람 수로 세지 않는다.

## 어떻게 갈라 두었나

**기본값은 그대로 Supabase 다.** relay 주소를 지정했을 때만 relay 로 간다.
둘을 동시에 구독하지 않는다. `src/v8/network.js` 의 `relayUrl()` 한 곳에서 고른다.

- `VITE_LANTERN_RELAY_URL` 환경변수, 또는
- `localStorage['hanmaum-deungbul-relay']` (기존 등불사장과 같은 키)

`wss://` 또는 `ws://` 형식이 아니면 무시하고 Supabase 로 간다.

## v1 과 v8 은 방 이름으로 갈린다

기존 protocol v1 은 등불사장·도량·대법당용이라 **v8 과 모델이 다르다.**

| | v1 | v8 |
|---|---|---|
| 장면 | yard·grounds·hall·campus (4) | campus·workshop·temple1·lobby2·lobby3·terrace2·terrace3·hall5·seosan (9) |
| 좌표 | x, z | x, **y**, z (층이 있다) |
| 생김새 | `{sex, color}` | `{gender, hair, skin, hairColor, robeColor}` + outfit |
| 이름 | 12자 | 24자 |
| 사건 | say·lit | chat·gesture(hapjang·bow) |
| 장면 바꾸기 | **거절**(join 때 고정) | 허용(걸어서 오간다) |

그래서 v1 을 고치지 않고 **프로필**로 갈랐다. `workers/lantern-room/src/profiles.js` 에
`V1_PROFILE`·`V8_PROFILE` 이 있고, `room.js` 는 프로필을 통해서만 장면 경계·좌표 검사·
명단 모양을 본다. 방 이름(`campus-v2` / `v8`)으로 고른다.

프로필은 DO 저장소에 같이 넣는다. 최대절전에서 깨어날 때 같은 것으로 복원해야 한다.
예전에 저장된 방에는 이 값이 없어 v1 으로 떨어진다. 그때는 v1 뿐이었으니 그게 맞다.
사람이 들어 있는 방의 프로필은 바꾸지 않는다. 명단 모양이 섞인다.

## 걸린 것들

- **hello 를 보낼 때.** 이름·생김새는 첫 presence 가 와야 안다. `onopen` 에서만 보내면
  이미 열린 소켓에는 영영 가지 않아 서버가 10초 뒤 `hello_timeout` 으로 끊는다.
  소켓이 열린 순간과 생김새를 알게 된 순간 **둘 다** 에서 보낸다(`ensureHello`).
- **장면 바꾸기.** v1 서버는 `pose` 의 장면이 다르면 `bad_scene` 으로 **연결까지 끊는다.**
  v8 은 아홉 장면을 걸어서 오가므로 `profile.allowSceneChange` 로 갈랐다.
- **퇴장.** 그냥 끊으면 서버가 45초 동안 `연결 확인 중` 으로 잡아 둬서 남들 화면에
  멈춘 사람이 남는다. 일부러 나갈 때는 `bye` 를 보내 바로 뺀다. 끊긴 경우의 유예는 그대로 둔다.
- 시험 중 한 번 비대칭으로 안 보인 적이 있는데, **이전 실행의 로컬 DO 저장 상태가 남아서**였다.
  `.wrangler/state` 를 지우면 사라진다. 코드 문제가 아니다.

## 검증한 것

`wrangler dev --env staging --local` 로 **진짜 Durable Object** 를 띄우고 확인했다.
Cloudflare 계정 없이 로컬에서 돈다.

- 두 클라이언트가 서로 봄, 위치·회전·생김새 전달 ✓
- 대화 전달, 내가 보낸 것은 되돌아오지 않음 ✓
- 장면 전환(campus → hall5)과 **높이 y=4.4** 전달 ✓
- `bye` 로 즉시 퇴장, 상대 인원 0 ✓
- **진짜 브라우저 두 탭**(Playwright, vite dev): 양쪽 다 `2명 접속` 표시 ✓
- 그때 연 WebSocket 은 relay 하나뿐. **Supabase 를 같이 붙잡지 않음** ✓
- 깃발을 빼면 Supabase 로 붙음. 기본 경로 그대로 ✓
- `tests/v8-relay.test.mjs` 10개 포함 저장소 216개, 워커 43개 통과 ✓
- `npm run build` 통과 ✓

## 아직 안 한 것

- **배포된 워커는 아직 옛 코드다.** `lantern-room-staging` 은 v8 방을 모른다.
  이 컨테이너에 Cloudflare 자격 증명이 없어 내가 배포할 수 없다. 배포는 아래 한 줄이다.

  ```
  cd workers/lantern-room && npx wrangler deploy --env staging
  ```

  그 뒤 브라우저 콘솔에서
  `localStorage.setItem('hanmaum-deungbul-relay','wss://lantern-room-staging.feelover7.workers.dev')`
  로 켠다. `ALLOWED_ORIGINS` 에 운영 주소가 이미 들어 있다.
- **실제 여러 기기·실측 지연·80명 동시는 재지 않았다.** 로컬 한 대에서 본 것이다.
- 무료 DO 예산은 80명·2Hz·2시간이 한도의 72% 다. **2시간 행사 한 번은 되고 같은 날 두 번은 안 된다.**
  그래서 기본값을 relay 로 바꾸지 않았다. 평소에는 Supabase 로 두고 행사 때만 켠다.
- 이를 80명 동시 접속 보장으로 표현하지 않는다.
