# 모바일 사용성 점검 — 2026-11-09

기준 main: 6b9378b28532e1a4d2dd4114c04c95347458a8c6. PR #20은 이미 병합되었으므로 최신 main에서 모바일 후속 작업을 시작한다. 독서 홈페이지와 법당 내부 모델은 수정하지 않는다.

## 코드에서 확인하고 수정한 문제

| 문제 | 개선 |
| --- | --- |
| 작은 화면에서 시작 그림 320px와 여백이 화면 폭을 초과 | 그림 최대 폭 제한, 시작 화면 세로 스크롤 |
| 노치/홈 표시줄과 조작부, 탑돌이 표시가 겹칠 여지 | safe-area 여백, 탑돌이 하단 배치, 진행 중 보조 HUD 숨김 |
| 모바일 이름/글 입력 때 키보드가 UI를 가림 | visualViewport 높이/위치 반영, 입력창 16px, 패널 내부 스크롤 |
| 터치 시점 확대 수단 없음 | 두 손가락 확대·축소 및 44px +/− 버튼 |
| 두 번째 손가락이 조이스틱을 빼앗거나 캡처 종료 후 이동 유지 | 단일 포인터 소유, 캡처 해제/숨김/초점 이동/화면 회전 시 초기화 |
| 법당 대화 버튼이 입력 초점을 캔버스로 되돌림 | 입력창에 초점이 있으면 유지 |
| 대화 전송 실패에도 입력 내용이 사라짐 | 실패 문구와 입력 유지, 전송 중 중복 방지, 새 입력 보존 |
| 작은 가로 화면에서 펼쳐진 HUD가 시야를 차지 | 터치 기기 기본 접기, 짧은 가로 화면 조작부 축소 |
| 일부 버튼이 44px보다 작음 | 주요 버튼·색상 선택·닫기 터치 영역 확대 |

공통 구현: mobileUi.js / mobileUi.css. sceneKit.js의 입력/대화 함수는 touchControls.js로 분리하고 기존 export 경로를 유지한다.

## 수행한 검증과 한계

- 도구 내 V8에서 실제 함수와 DOM 모형을 사용한 상호작용 검사 8개 PASS: 회전/핀치 전환, Ctrl 휠, 키보드 높이 복귀, 조이스틱 소유·해제, 줌 범위, 초점 유지, 전송 실패·성공, 비동기 중복/새 입력 보존.
- 수정 JavaScript의 구문 검사 PASS. 이것은 브라우저 또는 정식 Node 테스트 실행 결과가 아니다.
- 재현 가능한 테스트: `node --test tests/mobile-ui.test.mjs`.
- 현재 환경에는 터미널/브라우저/실기기가 없어 실제 렌더링, Safari 키보드 동작, 스크린리더, FPS/발열/배터리는 NOT RUN.
- 모바일 DPR 1.25, 그림자 비활성화, 화면 숨김 시 렌더 중단 설정은 기존 코드에서 확인했다. 속도 수치를 측정하지 않았다.
- 이전 main의 Worker 부하 시험 기록은 ORIGINAL_MAP_80_RESULTS.md에 보존한다. 모바일 80대의 동시 렌더링 시험과 구분한다.

## Claude / 실기기 확인 순서

1. 앱 빌드 및 위 테스트. 기존 worker·campus·camera 테스트도 실행한다.
2. Android Chrome / iPhone Safari에서 320×568, 360×800, 390×844, 가로 844×390 크기를 확인한다. 노치 기기의 실제 safe-area도 확인한다.
3. 시작 → 이름/색상 → 작업장 → 외부 → 법당 왕복. 버튼/안내/미니맵 겹침과 패널 스크롤을 확인한다.
4. 조이스틱 유지 중 다른 손가락으로 카메라 회전·핀치, 알림 전환/회전/복귀 후 캐릭터 정지를 확인한다.
5. 이름·소원·대화 키보드 열기/닫기, 한글 조합 Enter, 전송 실패 시 보존/재시도를 확인한다.
6. 자동 탑돌이 세 바퀴/중단, 법당 자동 구도 ↔ 자유 시점/확대/복귀, 삼배를 확인한다.
7. 실제 한국 모바일에서 장시간 FPS·프레임 지연·발열·배터리를 측정한다. 봇 80명 통신 통과를 모바일 성능 보장으로 쓰지 않는다.
