# v8 전시벽에 실제 등 · 한 줄 대화 · 걷는 속도 (2026-11-14)

기준 main `517fbd2`. 기획안(`docs/V8_PLAN_2026-11-14.md`)의 **①번**과,
그 작업 중 사용자가 말한 세 가지를 함께 했습니다.

## 1. 전시벽의 등 120개가 가짜였습니다

`public/v8.html` 의 전시장 벽에는 등이 120개 걸려 있었습니다. 그런데

```js
color: ['#da9b90','#e6c070','#b3bd8c','#96b9b2','#dcb184'][(r * 12 + c) % 5]
```

**색 다섯 가지를 돌려 쓴 하드코딩 장식**이었고, 누가 실제로 건 발원등과는 아무 관계가
없었습니다. 실제 등은 `showGallery()` 의 2D 창 안에만 있었습니다. 그래서 혼자 들어오면
벽은 꽉 차 보이는데 남이 남긴 것은 걸어 다니며 하나도 만나지 못했습니다.

### 바꾼 것

- 자리(120칸)만 `window.HanmaumExhibit` 한 곳에서 정하고, **무엇이 걸리는지는 실제
  발원등이 정합니다.** 걸린 순서대로 맨 아래 줄 왼쪽부터 채워 올라갑니다.
- `placed[i]` 는 언제나 `slots[i]` 에 앉습니다. 그리는 쪽은 색과 개수만 바꿔 끼웁니다.
- **세 렌더러가 같은 자리를 씁니다**: 3D(`workshop.js`), 2D 1인칭, 2D 위에서 보기.
  예전에는 세 곳에 격자가 따로 적혀 있었습니다.
- 빈 자리는 **빈 고리**로 남습니다. 비어 있다는 것도 보여야 합니다.
- **점등하면 등마다 제 색으로 빛무리가 켜집니다**(`workshopHalos`, opacity 0 → .5).
  `instanceColor` 는 diffuse 만 곱하고 emissive 에는 안 닿아서, 빛무리를 따로 뒀습니다.
- **벽 앞에 서면 가장 가까운 등의 이름과 발원이 화면 위 글자로 뜹니다.** 120개를 다
  띄우지 않고 하나만 봅니다. 3D 판으로 세우면 벽에 가려 잘립니다.
- **내 등에는 금색 테두리 고리**가 붙습니다.
- 120개가 넘으면 벽에는 최근 120개가 걸리고 나머지는 전시장 창에서 봅니다.
  `index` 를 보존해 창의 번호와 어긋나지 않습니다.

### 안전

- 이 브라우저에 저장된 등은 색이 무엇이든 들어올 수 있습니다. `exhibitColor()` 가
  `#rrggbb` 가 아니면 기본색으로 바꿉니다. **Canvas·THREE 에 임의 문자열을 넘기지 않습니다.**
- 이름·발원은 제어문자를 빼고 40자/180자로 자른 뒤 `textContent` 로만 넣습니다.

## 2. Enter 가 650px 모달을 열고 세계를 멈췄습니다

사용자: *"엔터누르면 채팅창이 뜨는게 좀 큰거같은데"*, *"채팅들이 왼쪽편에 보이게"*.

- Enter 는 이제 **한 줄 입력(`#quickChat`)** 을 엽니다. 모달이 아니라서
  `setPaused(true)` 가 걸리지 않고 세계가 계속 돕니다.
- 대화는 **왼쪽에 최근 다섯 줄(`#chatStream`)** 흐르고 14초 뒤 사라집니다.
  도량·대법당의 `한 줄 이야기` 와 같은 방식입니다. 머리 위 말풍선(10초)은 그대로입니다.
- 큰 창은 **`채팅` 단추에 그대로 남습니다.** 방 이름·접속·60줄 기록은 거기서 봅니다.
- Escape 로 닫습니다. **한글 조합 중 Escape 는 조합 취소라서 넘깁니다.**
- 입력 중에는 방향키가 캐릭터를 움직이지 않습니다(확인함). 닫으면 다시 걸어집니다.
- 휴대폰 키보드가 올라오면 `visualViewport` 로 그만큼 입력칸을 올립니다.
- 겹침: 입력칸이 열리면 `walkHint`·`firstGuide` 를 가립니다. 왼쪽 기록은
  `합장/반배/채팅` 상자(left 28, bottom 190, 높이 85) 위로 `bottom:288px` 에 둡니다.

## 3. 걷는 속도가 세 군데로 흩어져 있었습니다

사용자: *"도량 첫화면에서 걸어가는 속도가 너무 느린거 같은데"*. 재 보니 버그였습니다.

| 어디 | 전 | 후 |
| --- | --- | --- |
| 3D `setScene` | 6.4 | `HANMAUM_WALK(id)` |
| 2D `setScene` | 6.4 | 같음 |
| 3D 전용 도량 가속 | `campus → 8.6` | 없앰(한 곳으로) |
| 수행이 끝날 때 | **`4.3` 고정** | 그 장면의 속도 |

- **2D 대체 렌더러는 도량 가속을 아예 못 받고 있었습니다**(8.6 이 3D 프로토타입에만 있었음).
- **탑돌이·절 같은 수행을 한 번 하고 나면 두 렌더러 모두 4.3 으로 떨어졌습니다.**
  장면 속도로 돌아오지 않았습니다. 사용자가 느끼던 것이 아마 이것입니다.
- 이제 `globalThis.HANMAUM_WALK` 한 곳입니다. 도량 **11.5**, 나머지 6.4.
  도량은 조감 시점이라 같은 속도가 훨씬 느려 보입니다. 가장 먼 곳(등불사장 입구)이
  42.5 칸이라 6.6초 → **3.7초** 입니다.

## 확인한 것

로컬 dev 서버(운영 Supabase 읽기)에서 봤습니다. **쓰기는 하지 않았습니다.**

- 시험 245 + 워커 43 통과, `npm run build` 통과.
- **3D(swiftshader)**: 작업장 전시벽에 운영의 발원등 2개가 제 색으로 걸림
  (`paper.count=2, halo.count=2, ring.count=0` — 둘 다 남의 등이라 금 고리 0).
  점등하니 빛무리 opacity 0 → .5. 이름표 `클로드의 발원등 · 다른 법우의 등 /
  한마음으로 모두 평안하기를` 이 벽 앞에서 보임.
- **2D 대체 렌더러**: 같은 2개가 같은 자리(row 9, col 0·1)에 앉음.
- **대화**: PC(1280×800)·휴대폰(390×844) 모두 Enter → 한 줄 입력, 세계 안 멈춤
  (`paused:false`), 보낸 뒤 왼쪽에 쌓임, 입력 중 방향키로 안 움직임, Escape 로 닫고
  다시 5.2칸 걸음, `채팅` 단추는 여전히 큰 창.
- 도량 `walkSpeed` 11.5 확인.

## 확인하지 못한 것

- **실기기·실제 사람 여럿**. 이 컨테이너의 3D 는 소프트웨어 렌더라 약 3fps 입니다.
  걸어서 벽까지 가지 못해 자리를 직접 옮겨 찍었습니다. 걷는 속도 11.5 의 **체감**과
  휴대폰 조이스틱·실제 키보드 흐름은 재지 못했습니다.
- **등을 거는 쓰기**. 로컬에서 운영 DB 에 쓰지 않습니다. 새로 건 등이 벽에 바로
  붙는지는 배포본에서 봅니다(코드 경로는 `refreshExhibitWall()` 네 지점에 걸려 있음).
- 로컬에서 relay 는 `403 bad_origin` 입니다. 워커의 Origin 허용 목록대로이고
  회귀가 아닙니다. 운영 주소에서는 붙습니다.
- 날씨 API 429 는 이 컨테이너 IP 가 공용이라 나는 것입니다.
