# v8 다섯 가지 요청 (2026-11-14)

## 1. 걷는 속도

`walkSpeed` **4.3 → 6.4** (약 1.5배). 3D(`HanmaumWorld`)와 2D 대체(`HanmaumWorld2D`)
**두 렌더러 모두** 고쳤다. 한쪽만 고치면 WebGL 이 안 되는 기기에서만 느리다.

> **체감은 확인하지 못했다.** 이 컨테이너의 3D 는 소프트웨어 렌더라 3fps 여서,
> 방향키를 3초 눌러도 화면이 0px 움직인다. 숫자만 바꾼 것이고 실기기에서 봐야 한다.
> 빠르거나 느리면 이 값 하나만 고치면 된다.

## 2. 메뉴를 위아래키로 고르고 Enter 로 선택

- `이곳의 활동` 을 펼치면 **첫 항목에 초점**이 간다. 그래야 바로 위아래로 고를 수 있다.
- 초점이 메뉴 안에 있을 때만 ↑↓ 가 선택을 옮긴다. **메뉴 밖에서는 그대로 걷는다.**
  걷기 처리(`3D`·`2D`)와 전역 키 처리 **세 곳**이 `window.HanmaumMenuKeys` 를 먼저 보고,
  메뉴가 가져가면 걷지 않는다.
- 안내창이 떠 있으면 창 안의 단추들 사이를 돈다.
- Enter 는 단추가 알아서 누른다. 따로 가로채지 않는다.

확인: 펼침 → `본원 1층 무진향` 초점 → ↓ `2층 바깥·언덕길` → ↓ `3층 바깥·언덕길` → ↑ 되돌아옴.
Enter 를 누르면 그 항목이 실제로 눌린다(염탐으로 확인).

> 메뉴 항목을 고르면 **그 자리까지 걸어간다.** 바로 장면이 바뀌지 않는다.
> 이건 원래 그런 동작이고, 눌러도 Enter 로도 똑같다(둘 다 확인).

## 3. 접속자가 누구인지

머리 위 이름표는 원래 있었다(`HanmaumAvatar.createActor` 의 `label`). 다만 가까이 가야 보이고
화면 밖 사람은 안 보인다. **지금 붙어 있는 사람을 이름으로 적는다.**

```
hanmaum 도량 · 다른 법우 1명 연결 — 함동균
```

여덟 명까지 적고 나머지는 `외 N명` 으로 센다.

## 4. Enter 로 채팅 입력

게임 중 Enter → 대화창이 열리고 **입력칸에 바로 초점**이 간다. 확인: 창 `함께 접속 · 대화`,
초점 `chatInput`.

- 단추·링크·입력칸에 초점이 있으면 넘긴다. 메뉴에서 Enter 는 그 항목을 고르는 키다.
- 대화 단추를 누르는 것과 **같은 길**로 연다(`[data-ui="chat"]`). 다른 경로를 만들지 않았다.

## 5. 캐릭터 크기

바깥 마당 `1.12 → 1.45`, 실내 `1 → 1.18`. 전체 보기 구도는 건드리지 않았다
(사용자가 "전체적으로 보이는건 좋은데" 라고 했다).

> 3D 가 3fps 라 **크기를 눈으로 비교하지 못했다.** 숫자만 바꿨다.

## 확인 방법

3D 는 이 컨테이너에서 3fps 라 걸어 다니지 못한다. **WebGL 을 막아 2D 대체 렌더러로 돌려서**
메뉴·Enter·접속자를 확인했다. 전역 키 처리는 두 렌더러가 같은 코드다.
속도와 캐릭터 크기는 두 렌더러 모두 숫자를 바꿨지만 **실기기 확인이 남았다.**

`tests/v8-lanterns.test.mjs` 가 다섯 가지를 구조로 지킨다(235개 통과).
