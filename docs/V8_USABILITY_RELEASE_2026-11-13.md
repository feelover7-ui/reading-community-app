# v8 PC·모바일 사용성 수정
기준 main: d94d068ace3f9a9acc1adb1fa4e840db5da288c5. 사용자 ‘수정하고 배포해’ 승인.

## 수정
- 저장 검증에 2·3층 로비와 서산정을 포함해 9개 장소 방문 뒤에도 기존 진행을 읽는다.
- 유효한 recovery 원문을 다른 손상 기록이 덮지 않는다. 첫 화면/설정에서 현재와 보관 기록을 비교하고 명시적으로 복구한다. 복구 전 현재 기록은 -before-recovery에 보관하며 저장 실패 시 현재 진행을 유지한다.
- 눌림 효과가 중앙 정렬 transform을 덮던 제작 입력 오류를 수정했다. 골조 장식 SVG는 포인터 입력을 가로채지 않는다.
- 기존 제작 버튼을 그대로 실행하는 고정 하단 버튼으로 다음 단계를 안내한다. 다섯 단계와 난도·보상·게이트는 그대로다.
- 로비 2곳의 위치·대화·인사를 통신 검증에서도 허용한다. 기존 재접속/ref/초안/BFCache 보호는 유지한다.
- 첫 화면에 접속 상태 버튼, 연결 중 취소, 기기별 진행 안내를 둔다.
- 카메라 추적 거리를 넓히고 충돌 보호를 유지한다. 벽 때문에 시점이 가까워지면 내 캐릭터를 잠시 숨겨 화면을 가리지 않게 하고, 충분히 멀어지면 다시 보인다. PC 장소 목록은 기본 접힘, 대상 없는 작업 안내와 고정 조이스틱을 줄였다.
- 전시장은 소유한 등부터 표시하고 전체 360자리 보기로 전환할 수 있다.
- 모바일 메뉴의 초점 순환·Escape·배경 inert 복구, 안내 타이머 취소, 이름표 화면 가장자리 제한을 보완한다.
- 시설 위치·동선·자동 탑돌이·레벨 조건·게임 규칙·DB·환경변수·운영 의존성은 변경하지 않는다.

## 계획/판단 기록
실행 환경 연결이 끊겨 동일 main을 Vercel 임시 Sandbox에 받아 작업했다. 임시 .env.local은 기존 공개 프런트 설정만 사용하며 커밋하지 않는다.
저장 복구는 자동 덮어쓰기를 피하고 기존 사용자 진행을 비교한 뒤 선택하도록 했다.
독립 최종 검토가 발견한 메뉴 폭 전환 inert 잔류와 700px PC 버튼 겹침은 수정했다.
장소 이름의 추가 축약은 이번 변경에서 제외했다. 전체 접근성 이름은 유지하고 화면 가장자리만 제한한다.

- node --test tests/*.test.mjs: 184/184 통과. 새 저장/복구 11개, 모든 장소의 세 메시지 종류 검증 포함.

- Chromium PC 1440×900, 터치 모형 390×844: 실제 마우스/터치로 골조→전기→실묶기→배접→채색, 완성 등, 9개 장소 저장 검증, 새로고침 후 등·진행 유지. 키보드 제작 보조/카운터 주입 없음. pageerror 0.
- 실제 독립 Supabase 클라이언트 2개: 임시 qa 방에서 9장소 × presence/chat/gesture 송수신 통과. Broadcast/Presence만 사용, 운영 DB 쓰기 없음.
- 복구 UI PC/모바일: 미리보기 취소 시 이름 초안 유지, 확인 후 기록 복구 및 이전 현재 기록 백업 확인. 이 DOM 검증은 WebGL을 의도적으로 꺼 2D 대체 경로에서 실행했다.
- 모바일 메뉴 Tab/Shift+Tab/Escape와 fine-pointer 좁은 창→넓은 창 전환 확인. 실제 모바일 coarse-pointer는 폭이 넓어도 모바일 조작 UI를 유지하므로 별도 fine-pointer 검증으로 구분했다.
- 320/390 터치 및 600/700/800/1024/1440 PC 폭: 접속 버튼과 프로필/재화/소리/도움말/설정/메뉴 경계 겹침 없음. 이 DOM 검증도 WebGL 대체 경로다.
- scripts/qa-v8-v8.cjs, qa-v8-menu.cjs, qa-v8-recovery.cjs, qa-v8-layout.cjs, qa-v8-network.mjs에 재현 절차를 남겼다. 저장소 루트에서 실행하며 Playwright는 선택 설치한다. 기본 로컬 주소는 localhost:3000/v8.html이다. 네트워크 절차는 무시된 .env.local의 기존 publishable 설정만 읽는다.

실기기 iPhone/Safari, 실제 GPU 성능, 한글 IME, VoiceOver, 많은 인원 동시접속 부하는 검증하지 않았다. 소프트웨어 GPU에서 연속 장면 렌더를 멈추고 UI/입력/저장 로직을 검증했으므로 성능 보장으로 표현하지 않는다.
