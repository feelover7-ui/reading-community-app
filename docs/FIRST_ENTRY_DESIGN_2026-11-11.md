# 첫 접속 화면 기획 — 구현 전

사용자는 첫 접속 화면은 기획을 요청했다. 운영 첫 화면/등장 흐름은 이번에 수정하지 않고 시안과 설계만 제안한다.

## 현재 문제

현재는 등불사장 3D 소개와 준비 중→들어가기 뒤에 이름·성별·머리 모양/색·옷/색 전체 선택이 나온다. 어떤 활동을 할 수 있는지와 이동이 자동 안내된다는 점이 충분히 드러나지 않고 첫 방문 설정 부담이 크다. 초기 화면 뒤 전체 도량을 계속 렌더하지 않는 기존 성능 정책은 유지한다.

## 제안

첫 화면은 실제 앱에서 촬영한 정적인 도량 전경 한 장과 ‘천천히 걷고, 마음을 밝혀요.’라는 짧은 소개를 쓴다. 공식 문구 인용이 아닌 제안 카피다. 주요 버튼은 안내받으며 들어가기, 보조 버튼은 자유롭게 둘러보기다. 안내받기는 활동을 강제하는 투어 대신 기존 목적지 선택 안내로 연결한다. 자유 탐방은 이동을 시작하지 않고 안전한 도량 진입 지점에서 시작한다. 등 제작/참배는 서로 필수 조건이 아니다.

다음 화면에서는 이름/별명12자와 기존 presence에 필요한 기본 모습(m/f)만 정한다. 기본 모습의 선택지를 남성형/여성형으로 표시하는 안이다. 실제 성별 확인이나 로그인은 아니다. 기존 머리·옷 세부 설정은 들어간 뒤 옷 메뉴에서 선택하게 한다. 두 단계를 한 화면에 모두 넣는 방식보다 모바일에서 목적과 입력을 차례로 이해하기 쉽다.

다시 온 방문자는 저장된 별명/모습을 요약해 보여주고 이어서 들어가기와 안내받기를 제공한다. 이어서 가기는 저장된 제작 단계와 다음 작업대를 안내하며 자동 제작·자동 참배·저장 위치로 순간 이동하지 않는다. 이름/모습 수정 경로는 유지한다.

소리는 기본 꺼짐을 제안하며 들어간 뒤 명시적으로 켠다. 로딩은 실제 준비 단계(화면 준비/모델 준비 등)에 맞는 문구와 실패 시 다시 시도를 제공하고 가짜 진행률/무한 준비 중은 피한다. WebGL 미지원·초기화 실패 안내는 유지한다. 키보드 포커스/label/44px 터치 영역/동작 줄이기와 iPhone 세로 가로 화면을 확인한다.

## 비교한 방향

- 현재의 캐릭터 꾸미기를 먼저 강조: 개성이 보이지만 첫 방문 설정 부담이 크다.
- 첫 화면부터 실시간 도량 연출: 몰입감이 있지만 초기 로딩과 모바일 GPU 비용이 커진다.
- 정적 전경과 두 단계 시작(추천): 현재 도량을 소개하면서 실제 입장 전 렌더 비용과 선택 수를 제한한다.
