## 3. 고친 것 세 가지 — 왜 그렇게 했는지

### (1) `fadeOccluders` 의 죽은 변수 (PR #18 검증 중, `df39f29`)

### (2) 법당 자동 시점의 눈높이 (#23)

문 앞처럼 멀리서 보면 카메라가 많이 물러납니다. 각도 `.3` 을 그대로 쓰면 **눈높이가 천장(4.6)을 넘습니다.**
`beopdangScene` 은 카메라가 4.3 을 넘으면 천장을 걷어내므로, 걷힌 자리가 **화면 위의 빈 공간**이 됐습니다.

고친 방법: **거리는 그대로 두고 각도를 낮춰** 눈높이를 `HALL_EYE_MAX_Y`(4.05) 아래로 묶습니다.

**거리를 묶는 방법은 쓰지 마세요.** 해 봤습니다. 카메라가 캐릭터 쪽으로 당겨져서
이번엔 **화면 아래 3 분의 1 이** 법당 밖 바닥(그리지 않는 곳)이 됐습니다.
`tests/tapdori-camera.test.mjs` 에 눈높이 시험을 넣어 두었습니다 (3 해상도 × 7 자리).

### (3) 화면 배율 2 이상에서 캔버스가 잘리던 것 (#24)

`resize()` 의 `renderer.setSize(w, h, false)` — 세 번째 `false` 는 three 한테
"캔버스 CSS 크기는 건드리지 마라"는 뜻입니다. 그러면 캔버스가 **그리기 버퍼 크기(창 × 화면 배율)** 그대로 자리를 잡습니다.

| 화면 | 전 (캔버스 자리 / 창) | 후 |
| --- | --- | --- |
| 배율 1, 960×640 | 960×640 / 960×640 | 그대로 |
| 배율 2, 960×640 | **1920×1280** / 960×640 | 960×640 |
| iPhone 13 (배율 3) | **487×830** / 390×664 | 390×664 |

**배율 2 면 캔버스가 창의 두 배가 되어 왼쪽 위 4 분의 1 만 보였습니다.**
HUD 는 DOM 이라 멀쩡해 보여서 더 알아채기 어려웠습니다.

`deungbul.html` 은 `canvas#game{width:100vw;height:100vh}` 가 있어 가려져 있었고,
`anyangMap.css` 만 쓰는 `beopdang.html` 에서 드러났습니다. **CSS 에 기대지 말고 `resize()` 에서 맞춥니다.**
